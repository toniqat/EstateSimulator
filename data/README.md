# Data Module

Manages all game data loading and querying.

## Files

### dataLoader.js
Loads and provides access to all game data:
- Loads items (with stack limits)
- Loads facilities (including type field)
- Loads upgrade trees and costs (including grid dimensions)
- Loads game configuration values
- Loads production data for resource generation
- Loads crafting recipes
- Loads trading prices
- Loads product areas for grid-based facilities

Provides query methods to retrieve specific data items needed by game systems:
- `getProductAreasByFacility(facilityId)` - Get all production areas for a facility
- `getProductArea(areaId)` - Get a specific production area
- `getGridDimensions(facilityId, level)` - Get grid size for a facility at a level

### gameData.js
Auto-generated JavaScript file containing all game data embedded as a GAME_DATA object. This file is generated by BuildData.bat from CSV files in the data/ folder.

## CSV Files

These CSV files are used to generate gameData.js:
- **item.csv** - Defines all items with their stack limits
- **facility.csv** - Defines all facilities with their type (product, stash, trade, emply, process)
- **facilityUpgrade.csv** - Defines upgrade costs, progression, and grid dimensions (gridX, gridY)
- **production.csv** - Defines resource production rates and output items
- **recipe.csv** - Defines crafting recipes
- **trading.csv** - Defines buy/sell prices
- **gameConfig.csv** - Defines global game settings
- **productArea.csv** - Defines production areas that can be placed on product facility grids

## Important Notes

### Grid Dimensions
Grid dimensions are defined in `facilityUpgrade.csv` with columns `gridX` and `gridY`:
- Product facilities (farm, mine, ranch, fishery) have grid dimensions for each level
- Default level 1 facilities use 10x10 grids
- Grid size scales with facility level
- Non-product facilities have empty grid values

### Production Areas
The `productArea.csv` file defines areas that can be placed on product facility grids:
- Each area has a unique ID and references a facility_id
- Areas require a minimum facility level to unlock
- Areas occupy gridX x gridY cells on the facility grid
- Production logic is defined in a JSON-encoded `productItem` field containing:
  - `itemId`: Item produced
  - `itemProductCount`: Quantity per cycle
  - `itemProductTime`: Duration in seconds per cycle

## CSV Data Workflow

Game data is stored in CSV files and compiled by `BuildData.bat` into `gameData.js`. This allows configuration and content updates without code changes.

### Workflow Steps

1. **Edit** the relevant CSV file in the appropriate subdirectory:
   - Global config: `data/common/`
   - Workers: `data/workers/`
   - Facilities: `data/facilities/`
   - Items: `data/items/`
   - Trading: `data/trading/`

2. **Run** `BuildData.bat` from the project root to regenerate `gameData.js`:
   ```bash
   BuildData.bat
   ```

3. **Reload** the game in your browser to see changes immediately

### Data Compilation

`BuildData.bat` reads all CSV files in the `data/` directory structure and generates `gameData.js`, which is a JavaScript object containing all game configuration. This approach allows:

- Easy content updates without touching code
- Version control for all game data
- Batch updates across multiple CSV files
- Safe compilation with validation

### Important Notes

- **Changes take effect immediately**: After running `BuildData.bat` and reloading, all changes are live
- **Data is read-only at runtime**: The `dataLoader.js` module provides read-only access to prevent accidental modifications
- **No direct file editing after compilation**: Always edit the CSV files, never modify `gameData.js` directly
- **Rebuild required for changes**: CSV edits are not live—you must run `BuildData.bat` and reload the browser
